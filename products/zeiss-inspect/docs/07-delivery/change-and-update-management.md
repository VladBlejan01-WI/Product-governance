# Change and Update Management

**Current position:** Intake reports available vendor installation packages, service packs, and guidance, but no known formal upgrade/patch SOP. This proposed baseline is not an approved procedure.

## Proposed minimum change controls

1. Identify affected ZEISS INSPECT edition/version, ZEISS Quality Suite, Windows build/update, sensor/CT hardware, drivers, dongle/license mechanism, VMR, CAD integrations, and PLM workflow.
2. Review current ZEISS release notes and system requirements for the actual workflow; retain vendor references in controlled records.
3. Pilot the update with relevant metrology sites and representative optical/CT, CAD/PMI/MBD, PLM, reporting, and quality-validation workflows.
4. Obtain Quality/Metrology approval before changes impacting accredited, DAkkS-related, GPS-compliant, PPAP, qualification, or product-release measurement processes.
5. Record package provenance, test evidence, approval, rollout, rollback, and site/version baseline in approved operational systems.
6. Coordinate timing and communication across Detmold, TWG, WISC, and WIRO if the multi-site inventory confirms they are in scope.

Define named owners, required evidence, exception handling, patch cadence, rollback steps, and formal approval path before treating this as an SOP.
