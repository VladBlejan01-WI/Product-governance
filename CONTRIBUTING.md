# Contributing

This repository standardizes IT product documentation and governance for the portfolio. Changes should be precise, evidence-based, and aligned with the product ownership model.

## Expectations

- Use lowercase kebab-case for new folders.
- Use Markdown for documentation and YAML for structured product metadata.
- Keep references stable and maintainable.
- Do not add confidential evidence to Git.
- Use TBD only where necessary and only when the fact has not been validated.
- Prefer authoritative source references over assumptions.

## Review expectations

- Product documentation changes require product-owner review conceptually before merge.
- Changes affecting security, licensing, or architecture must be reviewed by the relevant specialists.
- Updates to evidence references must remain limited to approved controlled-record locations.

## Working patterns

1. Create or update the relevant product folder.
2. Update associated portfolio metadata and documentation.
3. Verify Markdown links locally where feasible.
4. Confirm no secrets, credentials, or confidential evidence are present in the repository.
