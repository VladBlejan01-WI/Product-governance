# Documentation principles

Documentation in this repository must be stable, useful, and evidence-based.

## Core principles

- Prefer factual, reviewable descriptions over assumptions.
- Keep the repository focused on governance and product documentation.
- Use TBD intentionally when a fact is not yet supported by authoritative evidence.
- Keep links readable and relative where practical.
- Avoid storing confidential and sensitive evidence in Git.

## Expected documentation types

- Product overviews and governance notes
- Portfolio catalog and risk views
- Architecture decision records and support boundaries
- Approved evidence references
- Governance process guidance and review checklists
